# ioccc代码分析(2)

时隔无数年，我又开始写博客了。翻了翻之前写的博客，翻到了多年之前的第一篇ioccc代码分析。那这次就继续分析另一个代码吧

```objectivec
main(_){_^448&&main(-~_);putchar(--_%64?32|-~7[__TIME__-_/8%8][">'txiZ^(~z?"-48]>>";;;====~$::199"[_*2&8|_/64]/(_&2?1:8)%8&1:10);}
```

csdn的编程语言里居然没有C，那就只好选传说中100%完全兼容C的Object\-C了，虽然这个语言应该已经死了。

上面的代码是纯C的，C\+\+编译不过的。编译之后，代码运行的结果是以感叹号和空格打印出来的一个字符画时间。每个数字是个6\*7的感叹号矩阵

 <img src="/assets/posts/64_1.png" alt="" style="max-height:231px; box-sizing:content-box;" />

看着还算比较短，我们来好好分析一下这个代码。

首先整理一下格式

```objectivec
main(_)
{
	_^448&&main(-~_);
	putchar(--_%64?32|-~7[__TIME__-_/8%8][">'txiZ^(~z?"-48]>>";;;====~$::199"[_*2&8|_/64]/(_&2?1:8)%8&1:10);
}
```

比之前的稍微好一点点。至少可以看出来第一句是main的递归调用。第二句是在putchar什么东西

我们先分析第一句 \_^448 && main\(\-~\_\);

很明显可以根据&&去拆分。而C语言基础过关的话应该知道&&有逻辑短路，就是只有前面为真的时候，后面的表达式才会执行。也就是说如果\_^448的值为假也就是0的时候，就会停止递归调用了。

那\_^448又在什么情况下为0呢？答案是\_为448的时候，^是异或操作，相同为0，不同为1\.

那 \-~\_ 这又是个什么操作啊？实际上就是 \_\+1 而已。你可以自己把每次调用前\-~\_的值打印出来看一下。至于为什么是答案是加一，这就不在这篇文章的范围内了。想了解的自行去补一下原码反码补码那些。

到这里为止，我们至少把第一句是分析完了，换个可读性强一点的写法吧

```objectivec
int main(int _)
{
//	_^448&&main(-~_);
	if (_ < 448) // _ != 448
	{
		main( _+1 );
	}
	putchar(--_%64?32|-~7[__TIME__-_/8%8][">'txiZ^(~z?"-48]>>";;;====~$::199"[_*2&8|_/64]/(_&2?1:8)%8&1:10);
}
```

接下来我们看下putchar里的东西。

我们看到了\-\-\_%64后面是一个问号，那第一反应应该是这里是三目运算符，后面还有个冒号。

那么这里就可以简化一下变成 putchar\(\-\-\_%64 ? \.\.\. : 10\);

中间最长的那一段我们最后再看。至少现在这里的结构还算清晰。

\-\-\_%64是先把\_自减1，然后对64取模。这里如果取模的结果为0，就会putchar\(10\),不为0就是那一长串。putchar\(10\)实际上就是输出一个换行符。ASCII 码10表示换行。可以猜测这里就是每输出64个字符会进行一次换行。

让我们把三目运算符换成if else。

```objectivec
int main(int _)
{
//	_^448 && main(-~_);
	if (_<448) // _^448    448^448=0
	{
		main(_+1);// -~_ = _+1
	}
	--_; //  [0, 447]
	if (_%64)
	{
		putchar(
			32|-~7[__TIME__-_/8%8][">'txiZ^(~z?"-48]>>";;;====~$::199"[_*2&8|_/64]/(_&2?1:8)%8&1
			);
		
	}
	else
	{
		putchar('\n'); // 10
	}
}
```

接下来就是整个代码最复杂的部分了。

如果对运算符优先级不是特别熟悉的话，我估计可能都分不清该怎么看吧。其实有个很简单的方法找优先级。加括号就好了，反正括号的优先级永远是最高的。

多试几次，就可以把它简化成这样

```objectivec
32| ( (7[__TIME__-_/8%8][">'txiZ^(~z?"-48]) +1 ) >> ";;;====~$::199"[_*2&8|_/64]/(_&2?1:8)%8&1
```

前面或运算32先不管它。\-~在前面就知道了，只是个加法而已。我们先看右移运算的左边部分。

7\[\_\_TIME\_\_ \- \_/8%8\]\[">'txiZ^\(~z?" \- 48\]

\_\_TIME\_\_是什么？\_\_TIME\_\_ 是一个编译时宏，表示编译时间的字符串，例如 `"12:34:56"` 。它会被替换为编译时的具体时间。

\_/8%8肯定是个数字，而且因为有取模运算，最后结果肯定是在0到7之间。

那这不是很有问题吗？对字符串还能理解，但怎么还有对字符串做减法的啊，这会减出来个什么东西啊？字符串就是指针，那减法不是会越界吗？

答案是它还真不会。为什么呢？看过我第一篇分析的应该会知道7\[a\]就是a\[7\]。我再补充一下，a\[7\]实际上就是 a\+7, 实际上就是&a\[0\] \+ 7。那么 7\[\_\_TIME\_\_ \- \_/8%8\] = \_\_TIME\_\_ \- \_/8%8\[7\] =  \_\_TIME\_\_\[7 \- \_/8%8\]。

所以这实际上是取出来字符串里的某个字符，取值范围是'0'\-'9'和 : 。而我们知道，字符本质上就是个8位的整数，所以这实际上也是一个数字。先把这个数记为x，那 x\[">'txiZ^\(~z?" \- 48\] = ">'txiZ^\(~z?"\[x\-48\]

现在就还有一个问题了，x\-48的结果怎么保证合法。这就得去查ASCII码表了。查了表就知道48是‘0’，而且 ':' 是 '9'的下一位。而 x的取值范围是 '0' \- ':'。那x\-48的值就可以限制在0\-10之间了。刚好，">'txiZ^\(~z?"的长度也是11。给出代码

```objectivec
int main(int _)
{
//	_^448 && main(-~_);
	if (_<448) // _^448    448^448=0
	{
		main(_+1);// -~_ = _+1
	}
	--_; //  [0, 447]
	if (_%64)
	{
		char ch = __TIME__[7 - _/8%8];
		//     32|-~ (7[__TIME__-_/8%8][">'txiZ^(~z?"-48]) >> ";;;====~$::199"[_*2&8|_/64]/(_&2?1:8)%8 &1
		putchar(32| ">'txiZ^(~z?"[ch-'0']+1 >> ";;;====~$::199"[_*2&8|_/64]/(_&2?1:8)%8 &1);
	}
	else
	{
		putchar('\n'); // 10
	}
}
```

右移前面的部分简化到这样已经差不多了，后面估计也差不多。现在的问题是，这么写的作用是什么？这就得结合">'txiZ^\(~z?"每个字符的ACSII的二进制和数码管的表示去理解了。

我们先把每个字符的ACSII的二进制列出来

能看出来点什么不？看不出来的往数码管显示方向去想想。

从上到下其实分别是0\-9每个数字的数码管显示的亮的管子。0是6根管，1是2根管，2是5根管。。。分割时间的冒号应该在这里就是只有一个点了

在这个基础上，我们再来看右移运算的后面 ";;;====~$::199"\[\_\*2&8|\_/64\]/\(\_&2?1:8\)%8是在干什么。

我们先按运算符优先级加一些空格方便阅读

```objectivec
( ";;;====~$::199"[(_*2&8) | (_/64)] ) / ((_&2) ? 1:8) % 8 
```

\_\*2&8，我们看到了与运算。可以想到这应该和二进制有关。\*2 的结果在二进制上就是左移一位，而&8 的结果就是第四位为1时结果为8，否则为0。因为前面有一次左移，所以实际上就是 \_ 的二进制第三位为1时，结果为8，否则为0\.

而\_ 的取值范围是限定在 \[0, 447\] 的，所以 \_/64 的结果是 \[0, 6\]。而这里的或运算实际上就是起一个加法作用。

所以当 \_ 从0开始递增的时候，\(\_\*2&8\) | \(\_/64\) 的结果呈现的规律是

```objectivec
0  0  0  0  8  8  8  8

1  1  1  1  9  9  9  9

2  2  2  2  10 10 10 10

...

6  6  6  6  14 14 14 14
```

数字以4个为一组变化。可以看到前面那个字符串的长度是14。算上末尾的'\0', 下标刚好可以到14。

有了前面的基础，\(\_&2\) ? 1:8 就简单很多了。&2 用来检查二进制第一位是否为0。第二位为1，则结果是1，否则结果是8。数字以两个为一组变化。

到这里其实整个代码就差不多了，写的也有点长了，稍微加点速收个尾。

前面的字符串的设计明显只是为了凑出来满足运算结果的。至于怎么凑出来的，这次先跳过，以后想写了再补。

结合最前面程序运行的结果，右移7位的都是输出空格，其他位数则根据">'txiZ^\(~z?"\[ch\-'0'\]\+1右移的结果是0还是1输出感叹号。每个数字的输出宽度都是6个字符，再跟两个空格。每个数字的一段数码管的宽度都是两个字符。

最后，为什么输出的感叹号和空格呢？因为，中间这一大段算完了之后，还要 32|\.\.\.&1，根据优先级，先与后或。与运算之后值要么是0要么是1，而这里或运算还是起一个加法的作用，所以运算的结果为32或者33。putchar的结果就是空格或者感叹号。ord\(' '\)=32，ord\('\!'\)=33

最后再贴个简化后的代码。

```objectivec
int main(int _)
{
	if (_<448) // _^448    448^448=0
	{
		main(_+1);// -~_ = _+1
	}
	--_; //  [0, 447]
	if (_%64)
	{
		char ch = __TIME__[7 - _/8%8];
		int mov = ";;;====~$::199"[(_*2&8) + (_/64)]/(_&2?1:8)%8;
		
		if (">'txiZ^(~z?"[ch-'0']+1 >> mov &1) putchar('!');
		else putchar(' '); 
	}
	else
	{
		putchar('\n'); // 10
	}
}
```

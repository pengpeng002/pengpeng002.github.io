# KMP真的比暴力匹配更快吗？这真不一定

先说结论，在绝大多数情况下，暴力实际上比KMP更快。

相信每个学过数据结构这门课的人都对不会对KMP算法这个名字感到陌生，会不会暂且不说，至少绝对听过。每一本教KMP的书都会告诉你KMP的时间复杂度是O\(m\+n\)，而暴力匹配的最坏情况下会达到O\(mn\)。一直到昨天为止，我都深深的相信着：KMP比暴力更快。嗯，到昨天为止。

就像快速排序在最坏情况下会退化成插入排序，但这并不影响快排的广泛使用，在大多数情况下，快排实际上是最快的。所以，我们要讨论一个算法的性能，应该是考虑它的平均时间复杂度而不是最坏时间复杂度。

所以，问题来了，暴力匹配的平均时间复杂度是多少？你可别脱口而出告诉我O\(mn\)哦。正确答案是接近O\(n\)。

首先我们假设：

- 字符集大小：k ≥ 2

- 独立均匀分布：各字符出现概率相等且相互独立

- 主串长度：n ≥ m ≥ 1

import time

def brute_force(text, pattern):
    i = j = 0
    count = 0
    n, m = len(text), len(pattern)
    
    while i < n and j < m:
        count += 1
        if text[i] == pattern[j]:
            i += 1
            j += 1
        else:
            i = i - j + 1  # 主串指针回溯
            j = 0
    return (i - j, count) if j == m else (-1, count)

def build_next(pattern):
    m = len(pattern)
    next_arr = [-1] * m
    i, j = 0, -1
    
    while i < m - 1:
        if j == -1 or pattern[i] == pattern[j]:
            i += 1
            j += 1
            next_arr[i] = j
        else:
            j = next_arr[j]
    return next_arr

def kmp_match(text, pattern, next_arr):
    
    i = j = 0
    count = 0
    n, m = len(text), len(pattern)
    
    while i < n and j < m:
        if j == -1:
            i += 1
            j = 0
        else:
            count += 1
            if text[i] == pattern[j]:
                i += 1
                j += 1
            else:
                j = next_arr[j]
    return (i - j, count) if j == m else (-1, count)

int brute_force(string text, string pattern)
{
	int i=0, j=0;
	int count=0;
	int n=text.length(), m=pattern.length();
	while (i<n && j<m)
	{
		count++;
		if (text[i] == pattern[j])
		{
			i++;
			j++;
		}

		{

		}

void build_next(string pattern)
{
	int m=pattern.length();
	for (int i=0; i<len_array; i++)
	{
		next_arr[i] = -1;
	}

实际上没什么区别，KMP的耗时就是比暴力更高，但它比较次数真的比暴力更低。很神奇吧，怎么比较次数和耗时出矛盾了？这就是理论和实践的区别了。软件都是依靠硬件来运行的，而我们的电脑有个很神奇的东西叫cache（计组真是个好东西）。

**注意：上述代码kmp的count放错位置了，实际上kmp的比较\(执行\)次数约为暴力的两倍。这才是真正的暴力更快的原因**

暴力匹配的时间复杂度和KMP的时间复杂度都是O\(n\)（虽然KMP还有个O\(m\)的建立next时间，但由于m一般远小于n，所以对实际的运行时间没什么影响），但KMP的常数因子更小\(<span style="color:#fe2c24">更大</span>\)，所以在比较次数上，KMP的平均比较次数始终小于暴力匹配\(<span style="color:#fe2c24">但kmp还有个j==\-1的情况，虽然不是比较，但在计数时还是得算上去</span>\)，但因为是同级的，所以差距不大。

> SIMD（Single Instruction Multiple Data）技术通过并行处理多个数据元素来加速 `memcmp` 等内存操作。其核心思想是利用宽寄存器（如128位、256位或512位）一次性加载、比较多个字节，而非逐字节处理。
> 
> 
> 
> **SIMD 是单核指令级并行** ：
> SIMD 在单个 CPU 核心内利用宽寄存器并行处理数据（如一次比较 16/32/64 字节）， **不涉及多核协作** 。内存块的处理是连续的，每次处理一个 SIMD 寄存器容量的数据。
